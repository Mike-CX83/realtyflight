The governed pipeline — as built

Operator terminal today · phone at D11

Types (soon: speaks) the intent — “Photograph this property: the full exterior package.”

▼

Planner — the LLM live: gpt-5.1

PydanticAI, provider-neutral. Composes typed steps from the shot library (front-¾, orbit, rear, overhead — geometry-computed). Output type physically excludes ids, limits, boundaries: the envelope is injected server-side. ≤2 validator-fed repair rounds.

▼

Deterministic validator 15+ rules · waves 1–4

Sequence shape · numeric envelopes · boundary geometry including path corridors (concave-lot proof) · live battery / GPS / telemetry-freshness / backend capability. Deny by default.

▼

Human approval hash-bound

Named operator, binds to the exact plan hash (any edit voids it), 300 s TTL, live-checked reports only. Physical aircraft additionally require a typed confirmation phrase.

▼

Mission executor 13-state machine

Dispatch gate re-checks reality before every command · steps advance only on telemetry evidence · abort preempts & flies home · touchdown requires proof · idempotent bounded retries (saved a live flight on day 2) · manual override is terminal · circuit breaker beats everything.

▼

DroneBackend contract the portability proof

Core imports zero drone SDKs. One contract suite runs identically on every backend — “engine-certified” means the core can’t tell them apart.

▼

FakeBackend CI workhorse

Deterministic practice drone with scriptable faults — hangs, timeouts, battery crashes, stick input.

PX4 + MAVSDK → Gazebo flown

Real autopilot firmware, real physics. Camera: synthetic evidence ✓ · RTSP real frames parked → A7 (Linux/RTX)

⛓ Audit spine: every decision above — plans, verdicts, approvals, dispatches, evidence, faults, overrides — lands in an append-only SQLite event log. The log alone replays the mission. (180 tests · 12-test cross-backend contract · CI on every push)
